# Layout

<!-- cspell:ignore Aptos chenglou Carlito GPOS Kaushan -->

!> Layout requires an understanding of [Table of Contents](usage/table-of-contents.md) and [Bookmarks](usage/bookmarks.md).

`docx/layout` lays out a document's pages as Word would, when the document is written, to work out the page each heading and bookmark is on. `docx` then writes those page numbers into the document's tables of contents and page references.

Without it, their page numbers are blank until Word updates the fields, because they depend on how the document is laid out. Word only updates them when the document asks it to (`updateFields`) and the reader says yes, or when the reader updates the table. LibreOffice never fills in a table of contents' page numbers, so documents it converts to PDF have none.

It is opt-in. The page numbers are estimates: Word still works them out again when it updates the fields, such as when the reader updates the table.

It can also give what is on each page, with [`layoutDocument`](#what-is-on-each-page): the lines of each paragraph, with their text and where they are, the rows of tables, the footnotes and endnotes, and which header and footer each page shows.

## Importing

Layout comes with the `docx` package. Import it from `docx/layout`, and everything else from `docx`:

```ts
import { Document, TableOfContents } from "docx";
import { estimatePageNumbers, layoutDocument } from "docx/layout";
```

In a page without a bundler, load `dist/layout.umd.cjs` after `dist/index.umd.cjs` (or `dist/layout.iife.js` after `dist/index.iife.js`). It adds a `docxLayout` global, such as `docxLayout.estimatePageNumbers` and `docxLayout.layoutDocument`.

## Example

Give the document `estimatePageNumbers` as its `pageNumbers`:

```ts live
import { Bookmark, Document, HeadingLevel, PageReference, Paragraph, TableOfContents, TextRun } from "docx";
import { estimatePageNumbers } from "docx/layout";

const text = "The harbour was rebuilt after the storm, and this report sets out what it cost and what is left to do. ".repeat(12);

const doc = new Document({
    // Without updateFields, Word shows the page numbers as they are written, and doesn't ask to update them
    pageNumbers: estimatePageNumbers,
    sections: [
        {
            children: [
                new TableOfContents("Contents", { hyperlink: true, headingStyleRange: "1-3" }),
                new Paragraph({ children: [new TextRun("The costs are on page "), new PageReference("costs"), new TextRun(".")] }),
                ...[1, 2, 3, 4].flatMap((chapter) => [
                    new Paragraph({ heading: HeadingLevel.HEADING_1, children: [new TextRun(`Chapter ${chapter}`)] }),
                    new Paragraph(text),
                    new Paragraph({ heading: HeadingLevel.HEADING_2, children: [new TextRun(`Section ${chapter}.1`)] }),
                    new Paragraph(text),
                ]),
                new Paragraph({
                    heading: HeadingLevel.HEADING_1,
                    children: [new Bookmark({ id: "costs", children: [new TextRun("Costs")] })],
                }),
                new Paragraph(text),
            ],
        },
    ],
});
```

The page numbers are written into:

- the entries of each [Table of Contents](usage/table-of-contents.md) filled in from the headings
- each [`PageReference`](usage/bookmarks.md#page-references). One that shows its position relative to the bookmark (`useRelativePosition`) writes "above" or "below" when it is on the bookmark's page, by whether the bookmark is before or after it in the text, even in another column or table cell, and "on page" and the page as it shows it when it isn't, such as "on page 4", "on page iv" or "on page 1-2", as Word writes it. A bookmark in a footnote or endnote is on the page of the note's reference, as Word has it, even in the part of a footnote that goes on to the next page or in an endnote at the end of the document, and one that shows its position relative to it writes "on page" and that page, even on the same page. One in a footnote or endnote writes "on page" and its bookmark's page too, wherever the bookmark is, as Word writes it
- the [number of pages](usage/page-numbers.md#total-number-of-pages) of the document (`PageNumber.TOTAL_PAGES`) and of [each section](usage/page-numbers.md#total-number-of-pages-in-a-section) (`PageNumber.TOTAL_PAGES_IN_SECTION`), in the text, headers and footers. A section's is left blank when it shares a page with another section, or has a blank page before or after it

A page reference or number of pages in a format of its own, such as a template's `PAGEREF Results \* roman` or Word's `NUMPAGES \* Arabic \* MERGEFORMAT`, or a `SimpleField` such as `new SimpleField("PAGEREF Results \\* roman")`, is written in that format, as Word writes it: `\* Arabic`, `\* Roman` (IV), `\* roman` (iv), `\* ALPHABETIC` (D), `\* alphabetic` (d), `\* Ordinal` (4th), `\* ArabicDash` (- 4 -), `\* CardText` (four), `\* OrdText` (fourth), `\* DollarText` (four and 00/100) or `\* Hex` (4), or a picture of digits, such as `\# "00"` (04), `\# "#,##0"` (1,234, or three spaces and 4 for page 4), `\# "0.00"` (4.00), `\# "x##"` (two spaces and 4) or `\# "'page '0"` (page 4), in capitals with `\* Upper` (IV, 4TH or ON PAGE 4), `\* Lower` or `\* FirstCap`. A page reference in a format of its own writes the number of its bookmark's page without its chapter number, such as ii for page 1-2, and one that shows its position relative to the bookmark writes the number too.

Word writes the numbers of the page and section a PAGE or SECTION field is on itself (`PageNumber.CURRENT`, `PageNumber.CURRENT_SECTION`, and a `PageNumberElement`), so `docx` leaves them empty, but the lines they are in are laid out with the numbers Word writes: the page's number as the page shows it, such as `iv` or `2-5`, or in one of the formats above, and the section's, counted from 1. In a footnote or endnote, they are those of the page and section of its reference, as Word has them.

The numbers of captions, such as the 2 of "Figure 2", are written too. Each `SequentialIdentifier` is a SEQ field, which counts the SEQ fields of its identifier, such as `"Figure"`, up to it, so its number doesn't depend on the layout. It is counted as Word counts it: the SEQ fields of the text, in text boxes and hidden text too, in order, with an identifier in any capitals, or in quotes, counted as the same one. The switches written after the identifier, such as `new SequentialIdentifier("Figure \\r 5")`, are followed: `\r 5` starts the count again from 5, `\c` repeats the number before, or writes 0 before the first, `\n` is the next number, `\s 1` starts the count again after each Heading 1, or heading of a higher level, and `\h` hides the number, unless it is given a format. A `\* ARABIC`, `\* ROMAN`, `\* ALPHABETIC`, `\* Ordinal` (4th) or `\* ArabicDash` (- 4 -) writes it in that format, and `\* roman` and `\* alphabetic` in small letters. A heading's caption number is left out of its entry in the table of contents, as Word leaves it out.

## Opening the document in Word

Without `pageNumbers`, `docx` writes page references, tables of contents and SEQ fields as fields for Word to update, so Word asks "This document contains fields that may refer to other files. Do you want to update the fields in this document?" when it opens the document. With `pageNumbers`, they are written as they are, so Word shows them as they are written, and doesn't update them or ask. Leave `updateFields` off, and Word opens the document without asking.

A page number `docx/layout` couldn't work out, after it stopped (see [What it leaves blank](#what-it-leaves-blank)), is left blank, and stays blank in Word until the fields are updated: by the reader, such as by updating the table of contents, or by turning `updateFields` on. A wrong page number is worse than a blank one. The same goes for what `docx/layout` doesn't write at all:

- a page reference that shows its position relative to the bookmark (`useRelativePosition`) in a header or footer
- a page reference or number of pages in a format other than those above, such as `\* BahtText` or `\* Caps`, or with a picture Word's text isn't known for, such as one with text in it that isn't in quotes, `#` after the decimal point, a decimal point in a document whose settings give another decimal symbol, or an `x` that would leave out digits of the number
- a table of contents that lists no heading, or of captions or TC fields, which is left empty, and the entries of one given `cachedEntries` or `contentChildren`, which are left as they were given
- the page numbers of a table of contents that writes a SEQ field's number before each of them (`seqFieldIdentifierForPrefix`), such as 2-5 for page 5 of chapter 2
- a SEQ field in a format other than those above, such as `\* CardText` or `\# 00`, or past what the format writes, such as 781 in letters, for which Word writes an error
- a SEQ field with a bookmark after its identifier, which shows the number of the SEQ field at the bookmark
- a SEQ field with a switch not followed, such as `\c` with `\r`, or in deleted text, and the SEQ fields of its identifier after it, until one starts the count again with `\r`. So is a field with `\s` after a paragraph with an outline level but no heading style (`outlineLevel`), or another than its heading style's
- the SEQ fields in headers, footers, footnotes and endnotes, which Word writes as an error, "Error! Main Document Only.", and every SEQ field of an identifier that has one in a comment

Word still asks when:

- the document has `updateFields` on, which asks Word to update all of its fields
- a table of contents is given `beginDirty: true`

## Templates

[`patchDocument`](usage/templates.md) writes the page numbers of a template it fills in too, when it is given `estimatePageNumbers` as its `pageNumbers`. The pages are laid out once the patches are in, so the numbers are those of the filled-in document:

```ts
import * as fs from "fs";
import { Paragraph, patchDocument, PatchType } from "docx";
import { estimatePageNumbers } from "docx/layout";

const doc = await patchDocument({
    outputType: "nodebuffer",
    data: fs.readFileSync("Report template.docx"),
    patches: {
        summary: { type: PatchType.DOCUMENT, children: [new Paragraph("The harbour was rebuilt after the storm.")] },
    },
    pageNumbers: estimatePageNumbers,
});
```

The template is read as Word saved it, with its styles, theme, lists, settings, headers, footers and notes, and the numbers are written into its tables of contents, page references and numbers of pages, in its text, headers and footers. The numbers a template was saved with are those of the template before it was filled in, so one that `docx/layout` can't work out, after something it can't lay out, is left blank rather than kept. Its page references and tables of contents are written clean, as a document's are, so Word shows them as they are (see [Opening the document in Word](#opening-the-document-in-word)). The template's settings are kept as they are, `updateFields` (`w:updateFields`) among them, so a template that has it on still asks Word to update all of its fields when the filled-in document is opened. Leave it off in the template, and Word opens the filled-in document without asking, as it opens a document whose fields are written clean (see [Opening the document in Word](#opening-the-document-in-word) for what still makes it ask). What `estimatePageNumbersWith` returns works the same way.

A template can import other documents (`w:altChunk`), which Word turns into paragraphs and tables of the template's own when it opens it. A `.docx` it imports is laid out as Word lays it out: where it is imported, in the text, a table cell, a header, a footnote or another imported document, in the template's styles of the same names, its defaults, its theme and its settings, with the styles only the imported document has as they look there, and paragraphs of no style in its default style, its lists numbered on their own and its footnotes numbered with the template's, and without its own page size, margins, headers and footers. One whose formatting is kept (`w:matchSrc`) keeps its own paragraph and character styles, those of the template's names too, but takes the template's table styles, such as Normal Table, and its theme, and its last paragraph has none of its space after, as Word lays it out. One that ends in a paragraph of a content control or custom XML stops the layout, as which paragraph Word takes the space after off there hasn't been seen. The styles only the imported document has, where its defaults give no font or size, are in Word's own, Times New Roman 10. A bookmark of a name the template has is the template's. What the layout doesn't follow stops it (see [What it leaves blank](#what-it-leaves-blank)).

`patchDocument` doesn't add entries to a table of contents for the headings patches add. Word adds them when it updates the table.

## What is on each page

`layoutDocument` lays out a document's pages as `estimatePageNumbers` does, and gives what is on each of them:

```ts
import { Document, Paragraph } from "docx";
import { layoutDocument } from "docx/layout";

const doc = new Document({ sections: [{ children: [new Paragraph("The harbour was rebuilt after the storm.")] }] });

const { pages, stoppedAt } = layoutDocument(doc);
for (const page of pages) {
    for (const block of page.body) {
        if (block.type === "paragraph") {
            for (const line of block.lines) {
                console.log(`Page ${page.pageNumber}: "${line.text}", ${line.y} pixels down`);
            }
        }
    }
}
if (stoppedAt) {
    console.log(`Laid out up to ${stoppedAt}`);
}
```

Lengths are in pixels, 96 to the inch, from the top left corner of the page. The page numbers of tables of contents and page references are laid out as `estimatePageNumbers` writes them, whether or not the document is given it. `layoutDocument(doc, { guess: true })` lays out past what it would stop at, as `estimatePageNumbersWith({ guess: true })` does (see [Guessing past what it can't lay out](#guessing-past-what-it-cant-lay-out)).

The layout of the document, `DocumentLayout`:

| Property    | Type                    | What it is                                                                                                                                                                                                                        |
| ----------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pages`     | `readonly PageLayout[]` | The pages, in order                                                                                                                                                                                                               |
| `stoppedAt` | `string` or `undefined` | What the layout [stopped at](#what-it-leaves-blank), such as `"a table that text flows around"`. The pages are those up to there, the last of them with what was laid out on it. With `{ guess: true }`, what it has no guess for |

Each page, `PageLayout`:

| Property       | Type                                          | What it is                                                                                                                                                                                                           |
| -------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pageNumber`   | `string` or none                              | The page's number, as the page shows it, such as `"3"` or `"iv"`. None when Word's isn't known: when the section's page numbers start with a chapter number                                                          |
| `section`      | `number`                                      | The section the page starts in, counted from 0                                                                                                                                                                       |
| `width`        | `number`                                      | The width of the page                                                                                                                                                                                                |
| `height`       | `number`                                      | The height of the page                                                                                                                                                                                               |
| `textRunsDown` | `"fromRight"`, `"fromLeft"` or none           | When the page's text runs down it, as in Chinese and Japanese, whether its lines go across it from the right or from the left. Its lines are then down the page, as below                                            |
| `header`       | `"default"`, `"first"`, `"even"` or none      | Which of the section's [headers](usage/headers-and-footers.md) the page shows, by the name the section's `headers` give it. A section without one of them shows the one of the section before. None when it has none |
| `footer`       | `"default"`, `"first"`, `"even"` or none      | Which of the section's footers the page shows, in the same way                                                                                                                                                       |
| `body`         | `readonly (ParagraphLayout \| TableLayout)[]` | The paragraphs and tables of the body on the page, or the parts of them on it, in order                                                                                                                              |
| `footnotes`    | `readonly NoteLayout[]`                       | The footnotes at the bottom of the page, in order. The rest of one that goes on from the page before comes first                                                                                                     |
| `endnotes`     | `readonly NoteLayout[]`                       | The endnotes on the page, which follow the body                                                                                                                                                                      |
| `guesses`      | `readonly string[]` or none                   | With `{ guess: true }`, what the layout [guessed at](#guessing-past-what-it-cant-lay-out) while it laid out the page, such as `"a font not in the width tables"`. None when it guessed at nothing there              |

A paragraph, `ParagraphLayout`, is `{ type: "paragraph", index, lines }`, and a table, `TableLayout`, is `{ type: "table", index, rows }`. `index` is where it is among the paragraphs and tables of the body, or of its footnote or endnote, counted from 0, so a paragraph on two pages has the same `index` on both. It counts each paragraph docx writes, such as the entries of a table of contents, and the empty paragraph it writes at the end of each section but the last, which takes no room, so it isn't on any page.

Each line, `LineLayout`:

| Property    | Type     | What it is                                                                                                                                                                                       |
| ----------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `text`      | `string` | The text on the line, with the spaces where it wraps and a tab as `\t`, but not the hyphen where it breaks at a soft hyphen. The texts of a paragraph's lines, one after the other, are its text |
| `x`         | `number` | Where the room for the line starts across the page: the left of its column, or of the page's text, and the paragraph's indent, or beside a drawing that text wraps around                        |
| `y`         | `number` | Where the top of the line is down the page                                                                                                                                                       |
| `width`     | `number` | How wide the room for the line is, between the paragraph's indents, or beside a drawing                                                                                                          |
| `height`    | `number` | How tall the line is, with the paragraph's line spacing                                                                                                                                          |
| `textWidth` | `number` | How far its text goes from `x`, without the spaces at its end, and with the hyphen where it breaks at a soft hyphen                                                                              |

The text is lined up in the line's room as the paragraph's alignment says, so it starts at `x` when it is aligned to the left, `(width - textWidth) / 2` further on when it is centred, and `width - textWidth` further on when it is aligned to the right. Justified lines but the last fill it. A line with text on both sides of a drawing is two lines with the same `y`, the left first, and a side the next word doesn't fit on is a line with no text.

On a page whose text runs down it (`textRunsDown`), each line is a line down the page: `x` and `y` are the top left of its room, `width` how far across the page the line is, with the paragraph's line spacing, and `height` how far down the page its room is, between the paragraph's indents. Its text goes `textWidth` down from `y`, and the lines go across the page from the right, or the left, from the margin.

Each row of a table, or the part of a row on the page when it breaks across pages, `RowLayout`, is `{ index, y, height }`: which of the table's rows it is, counted from 0, the top of the row, and its height, with its borders. A table's header rows are repeated at the top of each page it goes on to, and go on to the next page or column with the row after them when none of it fits below them, with the paragraphs kept with the next before the table.

A footnote or endnote, `NoteLayout`, is `{ noteNumber, content }`: its number, as its reference shows it, such as `"1"` or `"iv"`, and its paragraphs and tables on the page.

A blank page that Word adds so a section starts on an odd or even page has nothing on it, and no header or footer, as Word prints it.

`layoutDocument` doesn't give the lines in table cells, in headers and footers, or where tables are across the page, yet. Each line is where Word puts it, to within a few twentieths of a point.

## What it follows

The pages are laid out with the widths and heights of the characters of the fonts Word documents use most: Calibri, Cambria, Arial, Times New Roman and Courier New, and of Office's other fonts that Word installs: Calibri Light, Aptos, Aptos Narrow, Trebuchet MS, Georgia, Verdana, Tahoma, Century Gothic, Consolas, Candara, Corbel, Constantia, Book Antiqua, Franklin Gothic Book, Gill Sans MT and Impact; and the heights of the lines of the Chinese, Japanese and Korean fonts Office has, and how far each goes below its baseline, such as MS Mincho, Yu Gothic, SimSun, Microsoft YaHei, PMingLiU and Malgun Gothic. The widths are those of the letters of Western and Central European languages, Turkish, Vietnamese, Greek and Cyrillic, of punctuation and the spaces other than U+0020, and of currency signs, arrows and mathematical symbols, as Word draws them in each font, plain, bold, italic and bold italic, and in each of the fonts, plain and bold, and in Calibri's, Cambria's, Arial's, Times New Roman's and Courier New's italics, those of Hebrew, Thai, the Arabic-Indic and Devanagari digits, box drawing, shapes such as `docx`'s bullets ● ○ ■, symbols and dingbats, which Word draws in the font, or in another where the font lacks them, such as Calibri's Thai in Tahoma and its ★ in Segoe UI Symbol, whose ascent and descent a line with them takes, but for Cambria's and Times New Roman's Devanagari digits, and in Arial, Times New Roman, Cambria and Courier New, plain and bold, those of Arabic's and Persian's letters in each of the forms Word joins them in, isolated, final, initial and medial, and of the lam-alef ligatures, which Word draws in the font, and Cambria's in Times New Roman. Word kerns Arabic's letters side by side in Arial, Times New Roman and Cambria, by pairs not yet known, so only Courier New's Arabic, and letters alone, or lam with an alef, which Word joins into one glyph, are laid out. A letter a font doesn't have, Word draws in another font, whatever the text's language, such as Gill Sans MT's Cyrillic, Greek and Latin letters with a macron in Calibri, and Book Antiqua's less common Latin letters, such as ƀ, in Cambria, which the layout measures as Word does where that font is Calibri, Cambria, Arial, Times New Roman or Tahoma, with a line as tall as that font's. Italic text in a font without an italic face, such as Tahoma or Impact, is as wide as the upright text, as Word slants it, and Word draws Trebuchet MS bold italic as its bold, slanted. Bold text in a font without a bold face, Calibri Light, Franklin Gothic Book and Impact, is in the bold Word makes itself: each character 20 thousandths of an em wider than the regular at any size, but for the spaces, kerned and joined as the regular, and its lines as tall. It follows:

- the document's styles, and each paragraph's and run's own formatting: fonts, sizes, bold, italics, kerning and ligatures (see [Kerning and ligatures](#kerning-and-ligatures)), capitals, and hidden text. A paragraph whose mark is hidden (`run: { vanish: true }`) is joined to the next, on its lines, as Word joins it, in its own alignment, indents, space before, tab stops and borders, and the next one's space after, and each line spaced as the paragraph whose text it ends in, from the line the next one's text starts on. One at the end of a content control is joined to the paragraph after it too. In a table sized to its text, the two size the columns as one. Where both are in a list, the next one's number is counted but not shown, so the paragraph after them has the number after it. One with no paragraph after it, before a table or at the end of a table cell or of the document, stays as it is. A paragraph with nothing shown whose mark is hidden, such as one of a hidden style, takes no room, whatever its formatting, as in Word: before another paragraph or a table, and at the end of the document, but for one at the end of a table cell, which is a line of its own. The paragraph after it keeps its own formatting, one in a list takes a number, its fields are counted where it is, and its bookmarks start with what is after it. The paragraphs around it go by its style for their contextual spacing, one kept with the next (`keepNext`) is kept with the paragraph after it, and two with the same borders either side of it are in one box, as Word lays them out. So does one that ends a section before a section that starts on its page and is otherwise alike. A page break or picture in hidden text takes no room either, and a footnote or endnote reference none, but Word lays out its note, and counts it in the numbers of the notes after it. Chinese, Japanese and Korean are in the run's East Asian font (`font: { eastAsia }`), or in MS Mincho when that font has none of their characters, as Word draws them. A right-to-left run (`rightToLeft`) is in the run's font, size, bold and italics for complex scripts (`font: { cs }`, `sizeComplexScript`, `boldComplexScript`, `italicsComplexScript`), as Word draws it
- lengths given with units, such as `margin: { top: "1in" }`, `size: "12pt"` or a table's `width: { size: "6in", type: WidthType.DXA }`, as well as those given in numbers. Word reads each as a whole number of twips: rounded down from inches, points and picas, and to the nearest from centimeters and millimeters, and a size in any unit rounded down to a half-point, so `size: "10.75pt"` is 10.5 points and `size: "1cm"` 28. It reads the minus sign of a negative length as the whole number's only, and adds the fraction: `"-10.7pt"` is -9.3 points, a position of `"-2.5pt"` lowers text 1.5 points, and `"-0.5mm"` and `"-0.3cm"` are as much more
- where lines break, as Word breaks them: at spaces, and at en, em, four-per-em and ideographic spaces, which go past the end of a line as spaces do, after hyphens, en and em dashes and zero-width spaces, and between Chinese and Japanese characters. A word breaks at a soft hyphen (`SoftHyphen`), at the last one whose part of the word and a hyphen fit on the line, as a word fits, with the hyphen at the end of the line, and again on the next line when the rest is longer than a line. A soft hyphen takes no room where the line doesn't break, and kerned text either side of it isn't kerned across it. A justified line squeezes a word with soft hyphens onto it whole where it would squeeze one without, and otherwise breaks it at the last soft hyphen whose part and hyphen it can squeeze on, unless a shorter part fits as it is with less than twice as much room as the longer part needs squeezed, as Word does. A word in a border breaks at its soft hyphens too, and one whose part before its first soft hyphen is longer than a line breaks after the last character that fits. Word doesn't break lines at the other spaces, such as the thin space, so neither does the layout. In text in Japanese or Chinese (`language: { eastAsia: "ja-JP" }`), Word's lists keep characters such as closing brackets and `、` from starting a line, and opening brackets from ending one, so the character before moves to the next line with it. Text with no East Asian language, or in Korean or English, has no such rules in Word. Korean, Thai and the other scripts without spaces between words break at their spaces, as Word breaks them, and a word wider than the line breaks after the last character that fits. A paragraph's `wordWrap`, which writes Word's "Allow Latin text to wrap in the middle of a word", lets the words of runs in an East Asian font or language break anywhere, as Word breaks them. Right-to-left paragraphs (`bidirectional`) break where left-to-right ones do. In a left-to-right one, a line of right-to-left words in a right-to-left run (`rightToLeft`) has room for the space after its last word when a right-to-left word follows it, as that space is in the line, between them, and the space between right-to-left and left-to-right words in runs that aren't right to left hangs past the end of the line, as Word lays them out
- spacing before and after paragraphs, line spacing, indents and tab stops. A decimal tab stop (`TabStopType.DECIMAL`) lines up the first full stop of the text after it, such as that of `$1,234.50` or `e.g. 7`, or the end of a number, of digits and commas, that comes first and has none, such as the `12` of `12%`, the `12,` of `12, 34` or the `1` of `1 234.5`, or else the end of the text, as Word lays it out. Past the end of the line, the text after a right, centred or decimal tab stop of the paragraph's own lines up with the end of the line, or of the next line when it doesn't fit, after text or at the start of a line, whatever the left, first line and hanging indents, and a left one takes a line of its own, below the text before it, and the text after it goes to the start of the next line, in a paragraph with a first line or hanging indent too, and at the start of a line in a paragraph indented on the left or right, as Word lays it out. A tab stop between the paragraph's right indent and the margin, left, right, centred or decimal, lines its text up with it on the line, past the indent, in a justified paragraph too. A word that doesn't fit after a tab goes on to the next line with the tab, which moves to its stop there, and breaks there after the last character that fits, or at a soft hyphen, as Word lays it out. Text in a border lines up with a tab stop by its box: a right stop with the end of the box, a centred one with its middle, and a decimal one with its text, and a box goes on round a tab in it. The other cases stop the layout (see below). A line in one font is as tall as Word makes it, to a fraction of a twip (a twentieth of a point): 268.55 twips for Calibri 11. A line in several fonts is as tall as Word makes it from the tallest of them above the baseline and the deepest below it, so a word of Courier New in a line of Calibri 11 makes it 275.53 twips, taller than either font's own line. A paragraph with no paragraph after it to join, before a table or at the end of a table cell or of the document, stays as it is, and the document's last paragraph keeps its section break and takes a line. A deleted table row (`TableRow`'s `deletion`) takes no room, nor does the space between cells around it, and the rows around it have one border between them, which is the deleted row's own when it has borders of its own, or, with space between cells, each their own, as without it. Nor does a table all of whose rows are deleted take room. A table style's formatting for the first and last rows and for bands of rows goes by each row's place among all the rows, the deleted ones too, so with the first row deleted the second isn't formatted as the first. Word still sizes the columns of a table to their text, or widens them for long words, by its deleted rows, and by deleted text, pictures, tabs, breaks, note references and paragraph marks, as they are written, though the lines are laid out without them. Deleted and inserted cells, comments and changes of formatting don't move the lines. A document that asks Word to hide its insertions and deletions, or its markup (`w:revisionView`), is laid out the same, as Word for Mac opens it in its own view
- tables, with their columns' widths (`columnWidths`, or their cells' widths), their rows' heights, cell margins and borders. The columns of a table given no widths are sized to their text, as Word sizes them: each as wide as its longest line, or narrower when they don't all fit, but never narrower than its longest word, and a column whose cells give it a width keeps it. A cell merged across columns (`columnSpan`) widens them where its longest line needs more room, each in proportion to how wide it is, and a table in a cell counts as wide as its columns. In a table whose cells all have widths, a column with a word longer than its cells give it is widened to fit the word, and the other columns are narrowed to make room, as Word does, unless the table's layout is fixed. A table with a width of its own in twips is fitted to it, as Word fits it: when its columns are narrower, they are widened in proportion, and when they are wider, they are narrowed toward their longest words, or, when its layout is fixed, whatever is in them, each by the same share of the room for its text. When a word is longer than the table, its column is as wide as the word, and the table goes past the margin. Without a width of its own in twips, or with all of the width, a table whose columns' longest words don't fit in the room has each column narrowed to a share of it in proportion to its longest word, whatever width its cells give it, and the words break across lines, as Word breaks them. A table of a share of less than the width (`WidthType.PERCENTAGE`) whose columns' longest words don't fit in its share is as wide as they are, up to the room, and past it is narrowed as one of all of the width. A table sized to its text, or of a share of the width, has half of each of its left and right borders inside the room it fills, outside its columns, as Word draws them, where one of a width in twips has them outside it. Where the rows of a table give a column different widths, each column is as wide as the widest a row gives it, and a cell merged across columns that is wider than they are widens the last of them, before they are fitted to the table's width, in twips or as a share of the width, or, without one, narrowed to the room, unless its layout is fixed. In [templates](#templates), a row that starts past the first column (`w:gridBefore`) gives it its width before it (`w:wBefore`), as a cell does. A word in a cell merged across columns that is longer than they are wide is shared among them in proportion to each column's longest word and its longest line, or its width, added together, as Word shares it, and those columns keep its width when the others are narrowed. A long word with more text beside it widens them as its line does. Rows break across pages between the lines of their cells, as Word breaks them, keeping to widow and orphan control and lines kept together, and with room on the page for the space after a cell's paragraph that ends there. They move to the next page whole when a cell would have none of its lines on the page, when they are kept whole (`cantSplit`), and when the page hasn't room for the height they are set to. A row kept whole, or whose paragraph is kept together, that is taller than a page moves to a new page and breaks there as other rows do, and a row set to a height taller than a page takes a page of its own, cut off at its bottom, as Word lays them out. The text of a cell merged down from such a row, or to it from a row above, goes in all of its set height, past the bottom of the page, and the rest goes on in the rows after it on the next page, keeping to widow control. The row's footnotes start at the bottom of the next page, one after the other. A header row set to a height taller than a page isn't repeated on the next page, and what comes after its table goes on the page after the one the table ends on, as Word lays it out. A row set to at least a height taller than a page, whose text is taller than a page too, breaks where its text does, and each part of it fills its page. In columns, a row kept whole, or whose paragraph is kept together, that is taller than a column goes down only the first column of each page, from the top of a new page unless it is at the top of this one, as a paragraph kept together does, and what comes after one set to a height taller than a column goes on the next page. Where a table breaks across pages, Word draws its bottom border below the last of it on the page, which takes room there too, or its cells' own bottom borders. Header rows are repeated at the top of each page and column a table is on, and they aren't left alone at the foot of a page: when none of the row after them goes there, as it is kept whole, kept with the next or set to a height, they go on to the next page with it, as Word moves them. The text of a cell merged down rows (`verticalMerge`) goes down from below the border above its first row across the others, to above the border below the last, and makes the last of them taller when it needs the room. Where one of its rows breaks across pages, its text breaks with the row, as far down the page as its lines go, keeping to widow control, as Word breaks it, and the rest of it goes on from the top of its rows on the next page, and on across the pages after. Where the page breaks between its rows, as the next is kept whole or set to a height, the text that doesn't fit in its rows on the page goes on in its rows on the next, all of it where widow control leaves none of it on the page. A table in a cell breaks with its row, between its own rows and in them between the lines of their cells, as Word breaks it: as a table in the text breaks, keeping to widow control, with its bottom border below the last of it on the page and its cells' margins around their lines on each page, and with its rows kept whole, or of a set height, moving to the next page whole. On the next page, Word draws its top border above the rest of it, and doesn't repeat its header rows. A table in a cell merged down rows breaks as one in a cell of a row, and so does one with cells merged down its rows whose text is in their first rows, or whose rows are all on the page. An empty paragraph that ends a cell after a table in it takes no room, as Word lays it out
- table formatting, as Word lays it out. Borders come from the table's style and the table (`borders`), side by side, from its cells (`TableCell`'s `borders`), and from the parts of its style for some of its cells. Where two cells meet, Word draws the heavier of their borders, by its width and a weight for its style, but makes room for the wider, so each row is as much taller as the widest border above its cells and below those above it. Double, triple and the other styles of border take the room Word gives them, such as three times their width for a double border, and a border's `space` adds to it. In [templates](#templates), an art border takes as many points above and below a cell's text as its size. A cell's text is as far in from its left and right edges as its margin, or half its own border there when that is more, whichever of two borders that meet Word draws. A row of an exact height (`HeightRule.EXACT`) has the border above it inside that height, and one of at least a height has it outside, as Word lays them out. A row is as tall as its tallest cell's text, with the largest margins above and below of its cells, which needn't be the same cell's. Space between cells (`cellSpacing`) goes around each cell and inside the table's edges, and the table keeps its width, its columns narrowed for the space as Word narrows them, or widened to it in proportion, the space aside, and a column with a long word widened for it as in a table without the space. Where its rows give a column different widths, they are evened out as in a table without it, unless its layout is fixed. Each cell's own borders take room inside it, left and right of its text as well as above and below it, and the table's own go around the space. Where such a table breaks across pages, Word draws its bottom border below the last of it on the page, and its top border above the rest of it on the next, but for below its header rows repeated there, which have it above them. A row's own space between its cells (`TableRow`'s `cellSpacing`) goes around its cells in place of the table's, at the table's edges too, as do its own borders (`w:tblPrEx`, in [templates](#templates)), and the table's columns are as wide as they would be without it, where the table has a width of its own and its cells have widths. Space given as a share of the table's width, or of the type `auto`, is none, as Word lays them out. A row whose first cell's first paragraph is kept with the next (`keepNext`) is kept on the page with the next row, or, for the last row, with the paragraph after the table, and rows kept together that don't fit on a page of their own start a new page and break where it ends. Text that runs up or down a cell (`textDirection`) makes a row of only such cells as tall as a line of its last paragraph's mark, and a row with other cells no taller, as Word breaks it into lines as long as the row is tall, and a row with it breaks across pages as other rows do, the text on the page of its first part. In a table sized to its text, its column is as wide as a line of each of its paragraphs with text, however long, with the space before and after them, its lines as far apart as Word lays them out at their line spacing: a quarter of their size further than their size in Calibri, and as far as across the page in Times New Roman, Arial, Cambria and Courier New. A long word in it widens nothing, and the table's other columns are sized as they would be beside any other column. Text down with East Asian characters upright is laid out as text that runs down, and across with them on their side as text across. A table sized to its text that is indented (`indent`) is sized in the room the indent leaves, and one indented by a share of the width (`WidthType.PERCENTAGE`) is laid out as though it weren't indented, as Word lays it out. The parts of a table style for some cells, such as its first row, its last column or its bands of rows, apply where the table turns them on (`tableLook`), and where it doesn't say, as Word turns them on: its first row and column and its bands of rows. A header of several rows (`tableHeader`) is the table's first row, all of it, with the parts for its corner cells in each of its rows, and the bands of rows start below it, as Word applies them, but for a header of three rows or more with the first row turned off, whose bands start at its first row. A table style's own cell margins apply to its cells, its rows kept whole (`w:cantSplit`) are kept whole, and its own row height doesn't apply, as in Word, and a part of it for some rows gives them its height, and keeps them whole, and not its space between cells. In [templates](#templates), a row's own table borders and cell margins (`w:tblPrEx`) apply to its cells, cells merged across columns as old versions of Word wrote them (`w:hMerge`) are one cell across them, and a cell whose text Word is told not to wrap (`w:noWrap`) has it wrapped all the same, and text fitted to its cell (`w:tcFitText`) is on one line a paragraph, as Word lays them out. In a table sized to its text, the one makes its column as wide as its lines, as though they didn't wrap, and the other as wide as its column in the table's grid. In [templates](#templates), an empty last paragraph of a cell whose mark is hidden (`w:hideMark`) takes no room
- sections, with their page sizes, margins, columns, headers and footers, how they start, and their page numbering. Page numbers are written in Word's number formats as Word writes them, such as roman numerals, letters, words ("twenty-one") and the numbers of other languages, but for those it leaves blank (see below), and with chapter numbers in front of them (`chapterHeadingLevel`), such as 2-5 for page 5 of chapter 2. Each column's lines are broken at its own width, so a paragraph that goes on into a column of another width is broken again there, as Word breaks it. Widow control counts the lines left for the next column as they are broken in the column before, as Word counts them, and a table sized to its text keeps the widths it was sized to in each column it goes on into, as Word keeps them, going past the edge of a narrower one. Columns before a continuous section break are evened out, as Word evens them out, unless a column break is in them or a section in them started in the next column, and the next section starts below the longest. A section that starts in the next column (`SectionType.NEXT_COLUMN`) starts in the next column of the page when the section before has as many columns and one is left, as Word starts it, and on a new page otherwise. When its own columns are of other widths, it is laid out in the page's, where they are and as wide as they are, as Word lays it out, and in its own on the pages after. Its footnotes are laid out in its own columns. A continuous section numbered afresh (`pageNumbers: { start }`) leaves the page it starts on its number, and numbers the next on from its own first number, as Word does: 8 after a section numbered from 7 starts on page 12. When none of it fits on the page before, the page it starts at the top of is its first, numbered 7. One that starts in the next column of a page numbers on through the document, as Word numbers it. A gutter is beside the page's text, or above it in a document that puts it at the top (`w:gutterAtTop`), as Word takes it from the page's height, on every page with mirrored margins too, and below a negative top margin, which the header doesn't push the text below. A paragraph kept together that is taller than a column goes down only the first column of each page, as Word lays it out, from the top of a new page unless it is at the top of this one, and what follows it goes on below it. In columns of different widths it does when it is taller than each of them. One taller than some of them but not others goes in the first column, from where it is, that it fits in, as Word moves it: from the top of a narrow first column to a wide second, and past a narrow second column to a new page, in 3 columns or more as in 2, and the paragraphs kept with the next before it go with it. Paragraphs kept with the next before one taller than each column go to the new page with it, unless they are at the top of the page already, and it moves on to the next page, as Word moves them, so they are alone on theirs. A section that ends with a table has a line below it for the empty paragraph that ends the section, as Word has it
- in [templates](#templates), the divisions of a web page that paragraphs are in (`w:divId`), as documents made from HTML have them, laid out as Word lays them out: a paragraph is indented by the margins left and right of its division and of the divisions that division is in, with the division's borders outside them as a paragraph's borders, and a division's paragraphs are in one box, with its margins above its first and below its last. And pages printed two to a sheet or folded as a booklet (`w:printTwoOnOne` and `w:bookFoldPrinting`), which Word lays out as the section's pages, as it does without
- a section's document grid (`grid`), as Chinese and Japanese documents and Word's templates for them have it. On a grid of lines (`DocumentGridType.LINES`), each line takes as many of the grid's lines (`linePitch`) as its own height needs, with its text in the middle, as Word lays it out: at 360 twips, a line of Times New Roman of up to 15.5 points takes one, and from 16 points two. Multiple line spacing takes the grid's lines times the spacing when that is more, so 1.08 lines are 388.8 twips, at least a height takes that height when it is more, and exact spacing is as it is without the grid. The space before and after a paragraph isn't put on the grid's lines, a line of space before or after (in lines) is one of them, and the room below the last line's text can go below the bottom of the page. The lines of table cells, headers and footers aren't on the grid, nor the lines above footnotes and endnotes, but footnotes and endnotes are. A paragraph whose `snapToGrid` is off, in documents Word made, isn't on the grid's lines. A grid of lines and characters (`DocumentGridType.LINES_AND_CHARS`) also adds its `charSpace`, in 4096ths of a point, after each character, and a quarter of a character more between Chinese, Japanese or Korean characters and Latin letters, as Word does. One that snaps to characters (`DocumentGridType.SNAP_TO_CHARS`) puts each Chinese, Japanese or Korean character in as many cells as it needs, as many cells as fit across a column at the size of the Normal style's text and the `charSpace` more, spread evenly across it, and the other text between them on a line in as many cells as it needs together, with text spaced out by its run (`characterSpacing`) as wide as it is spaced. In columns of different widths each column has cells of its own. A left tab, and a line beside a drawing, start at the next cell, Chinese, Japanese or Korean text at a right or centred tab ends at the stop, or is centred on it, in its cells, a picture in the line takes as many cells as it needs after the text before it, a word longer than its line goes on to the next, a word with soft hyphens breaks at the last whose part fits in the cells left, and a justified or distributed line isn't squeezed. Characters of indents are the grid's characters, an indent of part of one is rounded up to the next cell, and a hanging indent's other lines go that many more cells in, as Word lays them out. Footnotes are on the grid as the body is, and endnotes on the last section's grid. Kerned text is kerned on a grid of characters, and on one that snaps to characters takes as many cells as it needs kerned. On a grid of lines and characters, text in a font that isn't East Asian, such as digits in Calibri, has no quarter of a character beside Chinese, Japanese or Korean characters. Emphasis marks take their room in the line before it is put on the grid, with multiple line spacing and at least a height too. A run with `snapToGrid: false` isn't on a grid of characters, and headers and footers aren't. Sections whose text direction (`page: { textDirection }`) runs across the page are laid out as those without one
- text that runs down the page (`page: { textDirection: PageTextDirectionType.TOP_TO_BOTTOM_RIGHT_TO_LEFT }`, and the other directions down it of documents Word made), as Chinese and Japanese documents have it, laid out as Word lays it out: each line runs from the top margin to the bottom one, and the lines go across the page from the right margin, or from the left for the directions that put them that way, each as far from the one before as it is tall, on the section's grid if it has one. Chinese, Japanese and Korean characters in fonts whose characters are all an em, such as MS Mincho and SimSun, are an em down the line, and Latin text is on its side, as wide as it is across a page. Indents are from the top and bottom margins, and the space before and after a paragraph is across the page. Half-width katakana are on their side, half an em each. A tab to a left stop, a border around text or around the paragraph, emphasis marks, superscript and subscript, and a justified line with spaces take the room they take across the page, and a footnote goes below the text, at the left of the page. Two digits set across the line (`w:eastAsianLayout w:vert`) take as much room along it as the line is tall. A gutter is beside the right margin, a negative top or bottom margin is as far from the edge as a positive one, and a grid that snaps to characters puts its cells along the lines. The header and footer stay across the top and bottom of the page, and a header doesn't push the lines down. A section whose text runs down the page starts a new page after one whose text runs across it, as a continuous section does too, and a continuous one goes on on the page after text that runs down it the same way

## What it leaves blank

It stops at the first thing it can't lay out yet, and the page numbers of the headings and bookmarks after it are left blank, until the fields are updated in Word (see [Opening the document in Word](#opening-the-document-in-word)):

- a table that text wraps around (a table's `float`) where Word's way with it hasn't been seen: one in a table cell, a header or a footer, one lined up inline against anything but the text, one with a footnote in it before a table, one after a paragraph kept with the next, one before a table that goes past the top or bottom of the page's text, two that may not overlap and do, where one may, or lined up at the centre, or with no room on either side, and one going past the bottom of the page with footnotes, a distance from the text above it, a row of more than one line that would go on to the next page, which Word splits as a row of a table it doesn't flow around, a row taller than a page, or in columns

So does one placed against where its anchor is along its line (`HorizontalPositionRelativeFrom.CHARACTER`), one lined up inside or outside against anything but the margins, or the page down it, one that would go above the page's text with a distance from the text above it, and one that would go past the bottom of the page's text at the top of a page or a column, or only by its distance from the text below it. So does a line whose anchor's page changes as the text goes round it, a page whose text going round a table that text wraps around moves the table's paragraph to the next page, or that has to be laid out again for its drawings more than 5 times
- an equation Word builds up where its way with it hasn't been seen: brackets, a root's sign, an accent or a brace whose size Word's probes leave between two of Cambria Math's sizes, a superscript in a sum's or limit's lower limit, a fraction, a sum or a function beside a bracket or bar, where Word may put a thin space, a sum in a script's script, a box with a side hidden or struck through, an equation array lined up other than at one ampersand in each row, or spaced otherwise, a phantom that takes less than its part's room, pre-scripts, skewed and linear fractions, a character Cambria Math has no sizes of grown over or under a part, or one such as an arrow over a part too narrow for it made of its parts, and an empty part, where Word shows a placeholder; normal text (`normalText`), which Word draws in the paragraph's font, whose ink the layout doesn't measure; a digit in an alphabet other than bold and double-struck; a symbol Word has been seen to draw only next to itself, such as some arrows and set operators, beside other atoms, and a character Cambria Math doesn't have; formatting other than bold, spacing and a size of its own; an equation that doesn't fit on its line, which Word breaks after an operator in a line of text, and before one when displayed, with the lines after the first indented; more than one equation alone in a paragraph; an equation outside a paragraph; and equations in a maths font other than Cambria Math, which Word draws in Cambria Math only where the computer doesn't have it, or whose document's maths settings make fractions small, and displayed equations whose document's maths settings give them margins (`m:lMargin`, `m:rMargin`), which Word breaks one too long for them within

- a line whose multiple line spacing would go below the bottom of the page in a table row that breaks across pages, or above its paragraph's border below, a line whose room on a document grid would go into the footnotes at the bottom of the page, and a line of only pictures in a paragraph at multiple line spacing whose mark is in a larger font than the pictures' runs

## Guessing past what it can't lay out

Some documents would rather have page numbers that are nearly right than blank ones, such as one in a font `docx/layout` doesn't have the widths of. Give the document `estimatePageNumbersWith({ guess: true })`, and the layout goes on past each thing it would stop at, with the best guess it has, rather than leave the page numbers after it blank:

```ts
import { Document } from "docx";
import { estimatePageNumbersWith } from "docx/layout";

const doc = new Document({
    pageNumbers: estimatePageNumbersWith({ guess: true }),
    sections: [...],
});
```

Its guesses, by what it would stop at:

- text in a font that isn't in the width tables, isn't given as a file and isn't embedded is measured as the most similar font that is: Segoe UI as Calibri, a serif font such as Garamond as Times New Roman, a monospaced one as Courier New, and the others, such as Roboto, as Arial. Word draws them with their own widths, when it has them: in Word's PDF, Segoe UI was 1% wider than its guess and Garamond 3% narrower (`word-watertight-text.docx` TX18). Bold text in a font given or embedded without a bold face is measured as the most similar font of the tables too, and text in a font given or embedded that Office also offers is measured from the file. A character whose width in its font isn't known is measured as an average letter of the font
- kerning and ligatures Word's PDFs haven't shown are measured as the layout measures the rest: a pair whose kerning isn't known as if not kerned, a word longer than its line with ligatures with them, and text with ligatures either side of a soft hyphen as one word
- a date or time is measured as it is written, where Word writes the date and time it opens the document
- a setting or formatting the layout doesn't follow, such as hyphenation, a compatibility setting or mode, a document grid, a text frame or an indent in characters it hasn't seen, is laid out as if it weren't there, a page number in a format it can't write is written in figures, and a table whose widths it can't work out as Word does is sized as it sizes others. A table that text wraps around where Word's way with it hasn't been seen is laid out in the text, as one it doesn't wrap around
- what it can't read at all, such as a text box, an equation, ink, or a picture or shape that text wraps around in a table cell or a note, is left out, and the rest of its paragraph is laid out without it. Text with a phonetic guide is laid out as its base, what is written in a content control bound to custom XML as it is, and a footnote with a mark of its own as the others are
- where Word's rule for laying out a page isn't known, such as a footnote that would break in a paragraph kept together, the page is laid out by the rule `docx/layout` follows that is nearest to it
- page numbers that still change how the pages are laid out after three passes are written as the last pass worked them out

It still stops where it has no guess: at an imported document (`altChunk`) it doesn't lay out as Word does (see [Templates](#templates)), such as one in HTML, a content control bound to custom XML whose first block is a table, a table all of whose rows are deleted where what Word does with one of them isn't known, a picture, shape or chart that text wraps around where Word's way with it hasn't been seen, tables that text wraps around that may not overlap and do, and a footnote or table row it can't fit on a page with what it is kept with, or that would go on across pages in columns, which it can't lay out past at all.

The page numbers may then not be Word's. They are written clean all the same, so Word shows them as they are, without asking to update the fields, unless the document has `updateFields` on. What the estimator gives says where it guessed, in `guesses`: why it would have stopped, such as `"a font not in the width tables"`, and the page it was laying out then, counted from 1 for the document's first page, whatever number the page shows. The page numbers of what comes after it, from that page on, may not be Word's. With nothing to guess at, it gives what `estimatePageNumbers` gives.

`layoutDocument` takes the same option, and each page says what it guessed at on it:

```ts
const { pages } = layoutDocument(doc, { guess: true });
pages.forEach((page, index) => page.guesses?.forEach((reason) => console.log(`Guessed at ${reason} on page ${index + 1}`)));
```

Guessing is off by default, so the page numbers written are Word's, as near as `docx/layout` knows them, or blank.

## Kerning and ligatures

Word kerns text that asks for it (`kern` on a run or a style, `w:kern`) from that size up, and joins letters into ligatures in text that asks for them (`w14:ligatures`, which `docx` doesn't write, but Word's own Normal template has, as documents and templates Word made do). Word's Normal template kerns from 1 point, which `kern: 2` asks for, and has standard and contextual ligatures. The layout does both as Word does, from Word's PDF of every pair of the characters of Windows-1252 kerned in Calibri, Cambria, Arial, Times New Roman and Courier New, plain, bold, italic and bold italic, and the letters Word joined in them with each setting of its Font dialog, and from Word's PDFs of the same in Office's other fonts of the tables, with Normal's ligatures and with all:

- **Kerning** brings pairs such as "To" and "AV" nearer, and, in Arial and Times New Roman, an A, L, P, T, V, W or Y nearer the space beside it. Courier New kerns nothing. Pairs across runs of the same font, formatting and language are kerned too, but not across runs of other languages, which Word kerns apart, though it does across runs of other colours. Text kerned from a size larger than it isn't kerned
- **Ligatures**: Calibri joins ff, fi, fl, ffi, ffl, ft, tt, tti, ti and others, about 2% narrower than its letters, with standard ligatures and with all; and ch, ck, ct, st and ij with discretional ones. Times New Roman joins fi, fl, ff, ffi, ffl, fj, ffj and Th, much narrower, only with discretional ligatures, and Arial and Courier New join nothing. Cambria draws an f before some letters another way, as wide. Word joins no letters in text with space between its characters (`characterSpacing`), and joins them across runs as it kerns them. Text either side of hidden or deleted text, or of a paragraph mark that is hidden or deleted, which Word joins to the next, is kerned and joined as if the two were next to each other, which Word's PDFs haven't shown
- The glyphs ligatures make are kerned with what is beside them as Word kerns them
- **Office's other fonts** are kerned as their own files kern them, as Word kerns them, but for a no-break space, which Word kerns as the space in Trebuchet MS and Gill Sans MT, and not at all in Corbel and Constantia. Text with ligatures is kerned only where a font's kerning is in its `GPOS` table: Word leaves it without kerning in Trebuchet MS, Verdana, Tahoma, Impact, Gill Sans MT and Franklin Gothic Book, whose kerning is in their `kern` tables alone, whichever ligatures it has, and kerns the same text without ligatures, or with `none`. Calibri Light joins letters as Calibri does; Candara, Corbel and Constantia join ff, fi, fl, fb, fh, fj and fk, and ffi, ffl and the like, with Normal's ligatures and with all; Aptos and Aptos Narrow join ff, fi and fl, as wide as their letters, and fj too with all; Tahoma joins ff, fi, fl, ft and st and Consolas fi and fl only with all of them; and Georgia, Trebuchet MS, Verdana, Century Gothic, Book Antiqua, Gill Sans MT, Franklin Gothic Book and Impact join nothing. Word's PDFs showed their ligatures with Normal's setting and with all, so the layout stops at the others in a font that joins letters, and takes a font that joins none with all of them to join none with any. Italic text in a font without an italic face is kerned and joined as upright, and bold text in one without a bold face, which Word makes itself, as the face it makes it from

Where Word's PDFs don't show how it kerns or joins text, the layout stops, as [What it leaves blank](#what-it-leaves-blank) lists. Fonts given as files are kerned and joined from their own tables (see [Measuring fonts from their files](#measuring-fonts-from-their-files)).

## How close it is

Text in fonts made with the same widths as those five is measured exactly as them: Carlito as Calibri, Caladea as Cambria, Liberation Sans, Arimo and Helvetica as Arial, Liberation Serif and Tinos as Times New Roman, and Liberation Mono and Cousine as Courier New. Text in the fonts the document embeds (`fonts`) is measured from their files, as Word draws it in them, but for fonts Office also offers, which stop the layout: Word for Mac drew Pacifico, which a document embedded, in the copy Office downloads, whose letters are narrower than `demo/assets/Pacifico.ttf`'s. Text in Aptos, Office's default font since 2023, and Office's other fonts of the tables is measured with Word's own files of them: each word of a line of prose in each of them but Verdana, whose line Word's PDF broke in two, kerned and with ligatures as Word's Normal template has them, is within half a point of where Word puts it, across lines of 1,100 to 1,400 points. Text in other fonts, such as Garamond, stops the layout (see [What it leaves blank](#what-it-leaves-blank)), unless their files are given (see [Measuring fonts from their files](#measuring-fonts-from-their-files)). Hebrew, Thai, the Arabic-Indic and Devanagari digits, box drawing, shapes such as the bullets ● and ■, symbols and dingbats are measured as Word draws them in each font of the tables, plain and bold, and in Calibri's, Cambria's, Arial's, Times New Roman's and Courier New's italics, but for Cambria's and Times New Roman's Devanagari digits, and stop the layout in the italics of Office's other fonts, whose widths of them Word's PDFs haven't shown, as those Devanagari digits do. Arabic's and Persian's letters are measured in the forms Word joins them in, in Arial, Times New Roman, Cambria and Courier New, plain and bold. Side by side in Arial, Times New Roman and Cambria, which Word kerns by pairs not yet known, they stop it, and so they do in Calibri, which Word kerns too, and in the other fonts. Word doesn't kern Courier New's. Devanagari letters, which Word joins into forms of other widths, stop it too. Other characters the width tables don't have, such as Armenian letters and emoji, are measured as an average letter of the font, or an em for emoji. The Latin letters of the East Asian fonts that aren't monospaced, such as Yu Gothic, and East Asian fonts Office doesn't have stop the layout too.

Each change to `docx/layout` is checked against LibreOffice's layout of a set of documents, and against the pages Word marked in documents it saved. Word lays out some things differently from LibreOffice, so turn `updateFields` on if the page numbers must be Word's own once the document is opened in Word: Word then asks to update the fields, and works them out again. LibreOffice rounds the height of each line to whole twips, 269 for Calibri 11, so where a line only just fits on a page, it can be on the next page in LibreOffice and on this one in Word, and in `docx/layout`, which follows Word.

Laying out a document takes about 0.3 seconds per 100 pages in Node.

## Measuring with a page's fonts

By default, text is measured with tables of the widths of the characters of those five fonts, which `docx/layout` has with it, so it lays out the same pages in Node and in every browser. In a browser, it can measure text in the fonts the page has instead, with [Pretext](https://github.com/chenglou/pretext), which measures text with a canvas.

`docx` doesn't come with Pretext. Install it (`npm install @chenglou/pretext`), give its module to `measureWithPretext`, and give what that returns to `estimatePageNumbersWith`, as `measureWidth`:

```ts live
import * as pretext from "@chenglou/pretext";
import { Document, HeadingLevel, Paragraph, TableOfContents, TextRun } from "docx";
import { estimatePageNumbersWith, measureWithPretext } from "docx/layout";

// Until a font has loaded, the browser measures text in another one
await document.fonts.ready;

const text = "The harbour was rebuilt after the storm, and this report sets out what it cost and what is left to do. ".repeat(14);

const doc = new Document({
    features: { updateFields: true },
    pageNumbers: estimatePageNumbersWith({
        // Carlito is as wide as Calibri, for a page that has it and not Calibri
        measureWidth: measureWithPretext(pretext, { fontFamilies: { Calibri: "Calibri, Carlito, sans-serif" } }),
    }),
    styles: { default: { document: { run: { font: "Calibri", size: 22 } } } },
    sections: [
        {
            children: [
                new TableOfContents("Contents", { hyperlink: true, headingStyleRange: "1-3" }),
                ...[1, 2, 3, 4].flatMap((chapter) => [
                    new Paragraph({ heading: HeadingLevel.HEADING_1, children: [new TextRun(`Chapter ${chapter}`)] }),
                    new Paragraph(text),
                ]),
            ],
        },
    ],
});
```

Pretext only measures how wide words and spaces are. The rest is laid out as Word lays it out: lines break where Word breaks them, rather than where a browser would, tabs move to the paragraph's tab stops, and lines are as tall as Word makes them. Their heights still come from the tables, so the layout stops at text in a font that isn't in them, such as Garamond, as how tall Word makes its lines isn't known, unless its file is given too (see [Measuring fonts from their files](#measuring-fonts-from-their-files)) or the document embeds it.

- Pretext needs a canvas to measure with: an `OffscreenCanvas`, or a page's. Node has neither, so use `estimatePageNumbers` there.
- Load the fonts before the document is written, such as with `document.fonts.load('11pt "Calibri"')`. A font that hasn't loaded is measured as the browser's default font, and Pretext keeps the widths it measured.
- A font the page has under another name, such as a web font, is measured in the CSS font family `fontFamilies` gives it. Fonts not in it are measured in the font of their own name, or the browser's default font when the page doesn't have one.
- The page numbers are only as close to Word's as the page's fonts are to the fonts Word has. Laid out in Chrome with Word's own fonts, the headings of the documents `docx/layout` is checked against were all on Word's page.

`measureWidth` can be any function that measures how wide text is, in points, in a font with a name, size in points, and whether it is bold or italic:

```ts
import { estimatePageNumbersWith } from "docx/layout";

const canvas = new OffscreenCanvas(1, 1).getContext("2d")!;

const estimatePageNumbers = estimatePageNumbersWith({
    measureWidth: (text, { name, size, bold, italic }) => {
        canvas.font = `${italic ? "italic " : ""}${bold ? "bold " : ""}${size}pt "${name}"`;
        return canvas.measureText(text).width * 0.75;
    },
});
```

Space between characters, and text scaled wider or narrower, are added to what it measures, as the document's formatting gives them.

## Measuring fonts from their files

To measure text in other fonts as Word does, in Node or in a browser, give `estimatePageNumbersWith` their font files, as `fonts`:

```ts
import { readFile } from "node:fs/promises";
import { Document } from "docx";
import { estimatePageNumbersWith } from "docx/layout";

const doc = new Document({
    pageNumbers: estimatePageNumbersWith({
        fonts: [
            { data: await readFile("Aptos.ttf") },
            { data: await readFile("Aptos-Bold.ttf") },
            { data: await readFile("Aptos-Italic.ttf") },
        ],
    }),
    styles: { default: { document: { run: { font: "Aptos", size: 24 } } } },
    sections: [...],
});
```

In a browser, give it the bytes of a file the page fetched, such as `await (await fetch("Aptos.ttf")).arrayBuffer()`. `docx` doesn't come with any font files.

- **The files** are TrueType or OpenType fonts (`.ttf` or `.otf`), or collections of them (`.ttc`), as bytes: a `Uint8Array`, such as a Node `Buffer`, or an `ArrayBuffer`. Web fonts (`.woff` and `.woff2`) are compressed, and can't be read.
- **Each file is one face of a font,** such as Aptos Bold, **or a collection of faces,** such as Cambria and Cambria Math in `cambria.ttc`, each of which is measured. The name of each face and whether it is bold or italic are read from it. Give a file for each face the document uses. Bold text in a font without a bold file is measured as it would be without the files, so it stops the layout when the font isn't in the width tables, as Word makes the bold face itself, and italic text without an italic file is measured with the upright one. To measure a font with a file of another name, give the name the document uses, such as `{ data: carlito, name: "Calibri" }`, which every face in the file is given.
- **Widths** are the font's own. The layout stops at a character the file has no glyph for, as Word draws it in another font (see [What it leaves blank](#what-it-leaves-blank)).
- **Fonts Office offers**, such as Pacifico, Roboto or Lato, stop the layout, given as a file or not, as Word for Mac draws them in Office's own copy of them, which may not be the file given (see [Fonts the document embeds](#fonts-the-document-embeds)). Office's fonts of the width tables, such as Aptos, are measured from the file given.
- **Kerning** is applied as Word applies it: only to text that asks for it, with `kern` on a run or a style (`w:kern`), and only to text of that size or larger. `kern: 2` kerns text from 1 point, as Word's own Normal template does. The pairs are the font's, from its `GPOS` table, or its `kern` table when its `GPOS` table doesn't kern Latin text, and pairs across runs in the same font are kerned too. Text with ligatures in a font kerned by its `kern` table alone isn't kerned, as Word leaves it.
- **Ligatures** join letters as Word joins them, in text that asks for them (`w14:ligatures`): with the ligatures of the font's `GSUB` table of the kinds the setting names, such as the standard ligatures of Aptos's `ff`, `fi` and `fl` for Word's Normal template's standard and contextual ligatures. The layout stops at text a substitution of another kind in those features could change, such as Cambria's contextual ones.
- **The height of a line** is the font's, as Word for Mac works it out: the ascender, descender and line gap of its `hhea` table, or its typographic ascent, descent and line gap when the font says to use them, as Aptos does. The line goes that descent below its baseline, with the gap above the text, which is what a line of it and another font, or a picture, is made from.

Text in fonts without files is measured as it is without them: with the width tables, or as `measureWidth` measures it when it is given too.

### Fonts the document embeds

Text in the fonts a document embeds is measured from the files it embeds, with nothing more given to the estimator: the fonts `docx` embeds with the `fonts` option, each as the regular face of the font of the name it is given, and those a template Word saved embeds ("Embed fonts in the file"), each as the face Word embedded it as. Bold text in a font embedded without a bold face stops the layout, as it does with a file given without one. Text in a font Office also offers, such as Pacifico, Roboto or Lato, stops the layout, embedded or given as a file, but for Office's fonts of the width tables, such as Aptos: Word for Mac draws it in Office's own copy of the font rather than in the file, as it drew Pacifico in Office's copy, whose letters are narrower, so the page numbers of text in it wouldn't be Word's. Guessing (see [Guessing past what it can't lay out](#guessing-past-what-it-cant-lay-out)), it is measured from the file, as other apps, such as LibreOffice, draw it. A file the document embeds that isn't a font, or is damaged, is left out, so text in its font stops the layout. When a font the document embeds is given as a file too, the document's own file is measured.

```ts
import { readFile } from "node:fs/promises";
import { Document } from "docx";
import { estimatePageNumbers } from "docx/layout";

const doc = new Document({
    pageNumbers: estimatePageNumbers,
    fonts: [{ name: "Kaushan Script", data: await readFile("KaushanScript-Regular.ttf") }],
    styles: { default: { document: { run: { font: "Kaushan Script", size: 22 } } } },
    sections: [...],
});
```
